# ПОС — преподавательская оценка студентов

C# / .NET 8, `Microsoft.Extensions.DependencyInjection`, xUnit.

## Запуск

```bash
dotnet run --project src/Pos
dotnet run --project src/Pos -- --demo
dotnet test
```

Первая команда открывает меню. Вторая заполняет пример и сохраняет итоги в `results.csv`.

## Устройство

- `Gradebook` — журнал одного курса и корень агрегата. Студенты и критерии — сущности со своими ID. Оценка — объект-значение. При исправлении журнал заменяет её целиком.
- Фабрика `Evaluation.Create` проверяет студента, критерий и балл. Поставить 21 из 20 нельзя.
- `Journal` — фасад для меню. Через него можно выставить оценку, исправить её, отменить или выгрузить итоги.
- `Totals` — доменный сервис. Он переводит баллы в доли от максимума и считает среднее по весам на шкале от 0 до 10. Две стратегии определяют, как учитывать пропуск. Для текущего балла критерий пропускается, для итогового даёт ноль.

Архитектура — Ports and Adapters. Зависимости идут внутрь: `Ui → Services/Journal → Domain`. В `Services/Storage.cs` лежат репозиторий в памяти и запись CSV. Их подключает `AddPos()`.

## Паттерны GoF

- **Фабрика** — и новая оценка, и исправление проходят через `Evaluation.Create`. Если балл выходит за границы критерия, прежняя оценка остаётся в журнале.
- **Фасад** — для экспорта меню вызывает `Journal.Export`. Журнал собирает итоги студентов и передаёт готовые строки на запись.
- **Стратегия** — `CurrentRule` пропускает критерий без оценки, а `FinalRule` включает его вес в итог. Сам подсчёт в обоих случаях выполняет `Totals`.

## Ответы на вопросы

**Почему журнал — корень агрегата?**
Чтобы поставить оценку, нужны студент и критерий из одного курса. Журнал хранит и тех и других, а для каждой пары ID допускает одну оценку. При исправлении меняется запись по той же паре.

**Почему итог считается отдельно?**
Он зависит от нескольких оценок и весов критериев. `Totals` берёт их из журнала при каждом запросе. Поэтому после отмены оценки итог сразу учитывает пропуск.

**Что будет при расширении?**
- Новый формат выгрузки — своя реализация `IResultsWriter` и одна замена в `AddPos()`.
- Новое правило для пропусков — ещё одна стратегия `ITotalRule`. Расчёт весов остаётся в `Totals`.
- Для нескольких курсов понадобится выбирать журнал по ID курса. Сейчас репозиторий возвращает один журнал на весь сеанс.

**Какие тесты проверяют оценки и итог?**
В `DomainTests` есть проверка на исправление: сначала студент получает 10 из 20 за практику и 10 из 10 за защиту. С весами 3 и 1 выходит 6,25. Если исправить практику на 20, итог станет 10. Если потом отменить защиту, текущий балл останется 10, а итог упадёт до 7,5.

Отдельный тест пытается записать −1, 21 из 20 или оценку по неизвестному ID. После ошибки прежняя оценка должна остаться на месте. В `ServicesTests` вместо записи на диск используется `FakeResultsWriter`: тест смотрит, какой итог попал в ведомость. В `ConsoleUiTests` проверяется тот же путь через демо.

**Что сделал ИИ, а что вы?**
Первоначальный код подготовил ChatGPT. Первая версия получилась громоздкой в мелочах. Было стратегически вырезано:

- команды вида `оценка | 1 | 2 | 10`. Нужно было помнить порядок трёх чисел. Теперь меню по очереди спрашивает студента, критерий и балл;
- длинная инструкция с командами для ручного демо. Теперь достаточно запустить программу с `--demo`;
- отдельные методы меню для записи и отмены оценки. В каждом было по одному вызову журнала и сообщению о результате;
- пример регистрации тестовой выгрузки в README. Рабочий пример уже есть в `ServicesTests`;
- комментарий над фабрикой оценок. Проверки студента, критерия и границ балла видны в самом методе.

При проверке ещё было исправлено:

- в первой версии не было общего файла решения, для запуска тестов приходилось указывать папку. Добавлен `Pos.sln`, пути к проектам приведены к виду `src/Pos` и `tests/Pos.Tests`;
- консоль читала и писала напрямую через `Console`. Теперь потоки передаются в `ConsoleUi`, как в первом ДЗ. В тесте вывод демо можно прочитать через `StringWriter`;
- демо из меню добавляло Анну и два критерия в открытый журнал. При повторном запуске появлялись дубли. Теперь демо запускается отдельной командой и работает со своим журналом.

**Ограничения:** один курс за запуск, баллы и веса целые. Журнал хранится в памяти. В CSV сохраняются только итоги, восстановить из него оценки нельзя.
